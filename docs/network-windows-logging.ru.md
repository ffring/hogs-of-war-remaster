# Windows: журнал одной сетевой попытки Hogs of War

Ты работаешь на Windows второго игрока. Денис — хост на Mac, оба компьютера уже видят друг друга через Tailscale. Нужен пакет диагностики одного подключения DirectPlay, чтобы Кодекс Дениса мог найти место сбоя. Игру пока не запускай. Текущий HOST_IPV4 возьми из последнего сообщения Дениса; адрес изменился при смене клиента Tailscale. Пароли и ключи не нужны.

## Подготовь логи

Создай отдельную папку hogs-network-logs-<UTC timestamp> в своей рабочей папке. Запиши UTC с миллисекундами, местное время/часовой пояс, Windows build и версии Tailscale/пробы. Если сохранились сведения о предыдущем зависании, добавь точную команду, cwd, время начала/конца, PID, внешний лимит и причину принудительной остановки. Неизвестные поля оставь null.

Скачай из релиза v0.5.0-test файл Hogs-of-War-Network-Diagnostics-v2-20261104.zip. Сверь SHA256 по docs/network-diagnostics-v2.json в https://github.com/ffring/hogs-of-war-remaster и все файлы SHA256SUMS.txt внутри архива. Это новая проба версии2: исходник и библиотечный код обмена те же, исправлено продолжение поиска при тайм-ауте, добавлены этапы и общий watchdog. Старый EXE не используй.

Сохрани результат обычного ping HOST_IPV4 и tailscale ping с ограниченным числом запросов. Учитывай, что успешные pong через DERP означают связь, даже если tailscale ping возвращает код1 из-за отсутствия прямого пути. Из tailscale status --json сохрани только BackendState, Self и поля узла HOST_IPV4: Online, TailscaleIPs, Relay, CurAddr, RxBytes, TxBytes. Удали поля имён пользователей, email, ID/ключи и остальные узлы. Достаточно IP двух участников и их состояний.

Сохрани Find-NetRoute -RemoteIPAddress HOST_IPV4 и параметры выбранного IPv4-интерфейса: alias, index, metric и network profile. Для текущей пробы запиши полный путь/хеш EXE. Правила Defender Firewall прочитай только для этого EXE и связанных dplaysvr.exe, если они есть; нужны Enabled, Direction, Action, Profile, program, ports и RemoteAddress. Ничего не меняй в firewall и сетевых метриках на этой попытке.

## Согласуй запуск

Подготовь всё заранее и сообщи READY_FOR_TRACE. Запускай join только после нового сообщения, что хост выдал stage=ready и его срок ещё не истёк. Самостоятельные повторы и старый stage=ready не используй.

В одной попытке выполни нативный Windows EXE:

    .\dplay-probe.exe --join HOST_IPV4 --timeout 45

Перенаправь stdout и stderr в отдельные файлы, сохраняя весь JSONL с первой строки. Запиши PID, команду, cwd, UTC начала/конца и exit code. Новая проба сама завершится кодом124 с active_step, если COM/API зависнет. Внешний предел —75 секунд; опрашивай процесс/сессию каждые5 секунд и не путай yield инструмента с завершением. Если пришлось принудительно остановить, останови только созданный тобой PID и укажи точную причину и прошедшее время.

Пока процесс существует, раз в секунду снимай его TCP/UDP endpoints через Get-NetTCPConnection/Get-NetUDPEndpoint -OwningProcess. Если сокетами владеет dplaysvr.exe, добавь только эти связанные PID. Один раз сохрани список DLL этого процесса и пути/версии dplayx.dll, dpwsockx.dll, wsock32.dll, если доступны. Ошибку доступа отметь, не обходи её.

## Короткий захват пакетов

Предпочтительно одновременно записать до75 секунд трафика внутри игрового tailnet через штатную команду Tailscale:

    tailscale debug capture -o <папка-логов>\tailnet.pcap

Сначала проверь доступность команды и что в этом tailnet нет постороннего активного трафика или exit node. Захват закончи сразу после пробы, остановив только свой capture-процесс; системный tailscaled не останавливай. Если такой захват затронет чужой трафик или недоступен по правам, пропусти его и сообщи причину. Не включай захват всего интернета и не меняй настройки VPN. Для Pktmon как альтернативы нужен фильтр только по HOST_IPV4; чужие сессии/фильтры сохраняй. Для этого теста достаточно одного способа захвата, размер ограничь16МБ.

В отчёте посчитай пакеты по направлениям, протоколам и портам. Особенно нужны запросы UDP47624, ответы и новые TCP-соединения; DirectPlay4 также использует TCP/UDP2300–2400, но не отбрасывай остальные порты между двумя игровыми IP. Зафиксируй SYN/SYN-ACK/RST и адреса, которые DirectPlay передаёт внутри своих сообщений, если удастся разобрать. Сам по себе ping не подтверждает DirectPlay.

## Передай результат

Сделай report.json и ZIP: stdout, stderr, timestamps/command/exit, маршруты/профиль, относящиеся к пробе firewall-правила, endpoints/DLL и короткий PCAP при наличии. Укажи первый незавершённый begin-этап, все ok:false/active_step/HRESULT, был ли peer_exchange. Успех: peer_exchange с exit0 у обеих сторон; stage=ready и ping отдельно.

Передай архив пользователю для Кодекса Дениса. Логи не загружай в публичный GitHub. Steam config, пароли, токены, приватные ключи, auth-ссылки, весь реестр, память других процессов и несвязанные устройства не собирай. После сбора останови только созданные тобой процессы диагностики. Игра, файлы игры, VPN, firewall и чужие сессии остаются как были.
